## Features

- Adapt [devicePixelRatio](https://developer.mozilla.org/docs/Web/API/Window/devicePixelRatio).
- Reduce flicking when resized.
- Observe the parent element's dimensions.
- Simple ticker and timer

## API Reference {#api-reference}

`AnimationCanvas` renders a `<canvas>` and takes its attributes, such as
`className` and `style`. A ref reaches the `<canvas>`.

In Svelte and Vue the props are the same, written their way — `class` rather
than `className`, `bind:value` or `v-model`, snippets or slots for content. See
[Svelte](/docs/tutorials/svelte) and [Vue](/docs/tutorials/vue).

### Fixed vs Resizable

A canvas is fixed by default: `width` and `height` set its size in CSS pixels.
With `resizable` it follows the size of its parent element instead, so the
parent needs a size of its own. The two are exclusive, and passing `width` or
`height` together with `resizable` is a type error.

### Reactive Canvas

By default the canvas redraws on every animation frame. When the drawing is
driven by state rather than by time, set `animate={false}`: the canvas then
draws only when it has a reason to — when it mounts, when it is resized, and
**when the component re-renders**.

That last one is what makes `React.useState` work as the source of the
drawing. Pass the new `draw` and the canvas repaints; there is nothing to
memoize and no redraw to trigger by hand.

See [Reactive](#reactive) below for a working example.

:::tip

Writing `draw` inline is fine either way. The canvas is set up once and the
handler is swapped in place, so re-rendering never restarts the animation,
resets `count` and `elapsedTime`, or runs `init` again. Wrapping the component
in `React.memo`, or holding `draw` in a `useCallback`, is not needed.

:::
