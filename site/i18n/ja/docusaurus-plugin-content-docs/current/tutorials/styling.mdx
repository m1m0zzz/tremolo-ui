**tremolo-ui は CSS を配りません。** コンポーネントが受け持つのはマークアップの描画と、
値の管理と、ポインタ・キーボード・ホイールの処理までで、見た目は利用者のものです。
素の CSS でも CSS Modules でも Tailwind でも CSS-in-JS でも、アプリの他の部分で
使っているやり方をそのまま使えます。

## 🎨クラスは自分で当てる

**クラス名は配りません。** 各パートが `className` を受け取り、そこに渡したものが
その要素の持つ唯一のクラスになります。こちらのクラスを打ち消す必要も、
こちらのスタイルが勝手に当たることもありません。

```jsx
<Slider.Root className={theme.root} value={value} min={0} max={100} onChange={setValue}>
  <Slider.Track className={theme.track}>
    <Slider.Thumb className={theme.thumb} aria-label="Level" />
  </Slider.Track>
</Slider.Root>
```

`style` も同じです。複数の要素を描くパートは、中身用に `classes` を受け取ります
（`Slider.MarksOption` の `classes={{ mark, label }}` など）。`Piano` の鍵盤は
`keyProps` から届きます。

下のテーマが CSS Modules なのはこのためで、各ファイルがパートごとに 1 クラスを
export します。上のように結びつけて使ってください。

## 🚦状態

状態はクラスを足す形ではなく、要素の属性として乗っています。セレクタ 1 つで届きます。
**off の状態では属性そのものが付かない**ので、属性名だけがセレクタになります（`="false"` に
誤ってマッチすることがありません）。

各パートが持つ属性は、それぞれのページの **API リファレンス** に
載せています（[Knob](/docs/components/Knob/#api-reference)、
[Slider](/docs/components/Slider/#api-reference)、
[XYPad](/docs/components/XYPad/#api-reference)、
[NumberInput](/docs/components/NumberInput/#api-reference)、
[Piano](/docs/components/Piano/#api-reference)、
[PointsEditor](/docs/components/PointsEditor/#api-reference)）。よく使うのは
`[data-disabled]` と `[data-readonly]` です。

それ自体がコントロールである要素（`Knob`、`NumberInput.InputField`、ステッパー、
thumb の中の range input）には対応する ARIA（`aria-disabled` / `aria-readonly`）も
付いています。ARIA はコントロールが何であるかを伝えるもので、スタイルが読むのは
`data-` 属性です。

```css
.slider[data-disabled] {
  opacity: 0.5;
}
```

フォーカスを受けるのは実際の要素なので、`:focus` / `:hover` / `:focus-within` も
どこでもと同じように使えます。

## 📐カスタムプロパティ

コンポーネントの見た目に関する値はカスタムプロパティで、対応する prop はその値を
書き込むだけです。

```jsx
<Slider.Track thickness={16} />
// 以下と同じ
<Slider.Track style={{ '--thickness': '16px' }} />
```

prop、スタイルシート、inline style は同じ値を指定する3つの方法で、通常のcascadeで
優先順位が決まります。**既定値はコンポーネントではなくCSSにあります。** そのため、
すべてのinstanceへpropを渡さなくても、CSSルール1つでまとめて変更できます。

```css
.track {
  --thickness: 16px;
}
```

propへ渡した数値はpxとして扱われます。それ以外はそのまま書き込まれるため、
`'3rem'`、`'100%'`、`'auto'` も使用できます。

どのパートがどのプロパティを持つかは、それぞれのページの **API リファレンス** に
載せています（[Knob](/docs/components/Knob/#api-reference)、
[Slider](/docs/components/Slider/#api-reference)、
[XYPad](/docs/components/XYPad/#api-reference)、
[NumberInput](/docs/components/NumberInput/#api-reference)、
[Piano](/docs/components/Piano/#api-reference)、
[PointsEditor](/docs/components/PointsEditor/#api-reference)）。

テーマはその上に自分の変数を足します。下のテーマには `--thumb-size`、track の
`--axis`、鍵盤の種類ごとの色があります。これらはテーマが読むためにあるもので、
名前を決めるのもテーマの側です。

## 📋このサイトで使っているテーマ

ドキュメント中の例はすべて以下のファイルでスタイルを当てています。依存先ではなく
出発点なので、必要なものをプロジェクトにコピーして書き換えてください。

いずれもビルド不要の素の CSS で、カスタムプロパティ（`--knob-size`、
`--thumb-size`、`--active-color` など）を使っているため、よくある変更は
1 行の上書きで済みます。

**テーマが決めるのは見た目であって、位置ではありません。** 各パートの配置は
コンポーネント自身が行います（thumb は自分で flow から外れ、値の位置に中央を
合わせます）。そのため、自前のテーマで規則を書き忘れてパートが変な場所に飛ぶ、
ということは起きません。配置に好みの余地がある部分はカスタムプロパティで開けて
あり、thumb・mark・point の `--translate` で中央合わせをずらせます。

### ダークモード

テーマはページ側の目印を読みます。祖先の `.dark`、または
`[data-theme="dark"]` で、このサイトと Storybook が付けているものです。

```css
:global(.dark) .thumb,
:global([data-theme='dark']) .thumb {
  --color: oklch(64.5% 0.17548 266.373);
}
```

セレクタが 2 つ並んでいるのは、CSS Module では `:global` が書いた場所に
そのまま残るためです。自分のアプリでのダークの表し方（独自のクラス、あるいは
`@media (prefers-color-scheme: dark)`）に差し替えてください。
