**tremolo-ui は CSS を配りません。** コンポーネントが受け持つのはマークアップの描画と、
値の管理と、ポインタ・キーボード・ホイールの処理までで、見た目は利用者のものです。
素の CSS でも CSS Modules でも Tailwind でも CSS-in-JS でも、アプリの他の部分で
使っているやり方をそのまま使えます。

## 🎨クラス名

すべての要素に `tremolo-` で始まるクラスが付いているので、自前のラッパーを
挟まなくても素の CSS で届きます。

```css
.tremolo-knob-active-line {
  color: rebeccapurple;
}
```

名前はコンポーネントとパートに対応します。`tremolo-slider`、
`tremolo-slider-track`、`tremolo-slider-thumb`、`tremolo-slider-marks` のように。
すべては下のテーマに載っています。

## 🚦状態

状態はクラスを足す形ではなく、要素の属性として乗っています。セレクタ 1 つで届きます。
**off の状態では属性そのものが付かない**ので、属性名だけがセレクタになります（`="false"` に
誤ってマッチすることがありません）。

| 属性 | 対象 | 意味 |
| --- | --- | --- |
| `[data-disabled]` | 全コンポーネント | `disabled` が指定されている |
| `[data-readonly]` | 全コンポーネント | `readonly` が指定されている |
| `[data-dragging]` | `Knob` / `PointsEditor.Point` | ドラッグ中 |
| `[data-orientation="vertical\|horizontal"]` | `Slider` / `Slider.Track` / `Slider.Marks` / `Slider.MarksOption` | スライダーの向き |
| `[data-flipped]` | `Slider.Track` | 値が反対側から増える（`vertical` と `reverse` の一方だけが有効） |
| `[data-active]` | `Piano` の鍵盤 | その音が鳴っている |
| `[data-out-of-range]` | `NumberInput.InputField` | 値が `min` / `max` の外にある |
| `[data-fill]` | `Piano` | `fill` が指定されている |
| `[data-selected]` | `PointsEditor.Point` | 選択中のポイント |

それ自体がコントロールである要素（`Knob`、`NumberInput.InputField`、ステッパー、
thumb の中の range input）には対応する ARIA（`aria-disabled` / `aria-readonly`）も
付いています。ARIA はコントロールが何であるかを伝えるもので、スタイルが読むのは
上の `data-` 属性です。

```css
.tremolo-slider[data-disabled] {
  opacity: 0.5;
}
```

フォーカスを受けるのは実際の要素なので、`:focus` / `:hover` / `:focus-within` も
どこでもと同じように使えます。

## 📐カスタムプロパティ

コンポーネントの見た目に関する値はカスタムプロパティで、対応する prop はその値を
書き込むだけです。

```jsx
<Slider.Track thickness={16} />
// 以下と同じ
<Slider.Track style={{ '--thickness': '16px' }} />
```

prop、スタイルシート、inline style は同じ値を指定する3つの方法で、通常のcascadeで
優先順位が決まります。**既定値はコンポーネントではなくCSSにあります。** そのため、
すべてのinstanceへpropを渡さなくても、CSSルール1つでまとめて変更できます。

```css
.tremolo-slider-track {
  --thickness: 16px;
}
```

propへ渡した数値はpxとして扱われます。それ以外はそのまま書き込まれるため、
`'3rem'`、`'100%'`、`'auto'` も使用できます。

| コンポーネント | プロパティ |
| --- | --- |
| `Knob` | `--knob-size` |
| `Slider.Track` | `--length`, `--thickness`, `--active`, `--inactive` |
| `Slider.Thumb` | `--thumb-size`（`Slider`に指定）、`--color` |
| `Slider.Marks` | `--gap` |
| `Slider.MarksOption` | `--thickness`, `--length`, `--gap`, `--label-width` |
| `XYPad.Area` | `--width`, `--height`, `--min-width`, `--min-height`, `--color` |
| `XYPad.Thumb` | `--thumb-size`（`XYPad`に指定）、`--color` |
| `PointsEditor` | `--width`, `--height` |
| `PointsEditor.Point` | `--width`, `--height`, `--color` |
| `PointsEditor.SelectionBox` | `--color` |
| `Piano` | `--height`と、下記テーマの鍵盤ごとの色 |

### `--percent`とfillの描画

`Slider.Track` は現在値の位置を`--percent`でも公開します。CSSだけでは算出できない
唯一の値であり、コンポーネント自身がfillを描画しない理由でもあります。fillは
パッケージが描く要素ではなく、テーマのルールです。

```css
.tremolo-slider-track {
  background: linear-gradient(
    var(--axis),
    var(--active) var(--percent),
    var(--inactive) var(--percent)
  );
}
```

このルールを置き換えれば、別の色、画像、値に応じて埋まる目盛りなど、任意のtrackを
描画できます。

## 📋このサイトで使っているテーマ

ドキュメント中の例はすべて以下のファイルでスタイルを当てています。依存先ではなく
出発点なので、必要なものをプロジェクトにコピーして書き換えてください。

いずれもビルド不要の素の CSS で、カスタムプロパティ（`--knob-size`、
`--thumb-size`、`--active-color` など）を使っているため、よくある変更は
1 行の上書きで済みます。

**テーマが決めるのは見た目であって、位置ではありません。** 各パートの配置は
コンポーネント自身が行います（thumb は自分で flow から外れ、値の位置に中央を
合わせます）。そのため、自前のテーマで規則を書き忘れてパートが変な場所に飛ぶ、
ということは起きません。配置に好みの余地がある部分はカスタムプロパティで開けて
あり、thumb・mark・point の `--translate` で中央合わせをずらせます。
